Não foi fixado formato de serialização nem catálogo nesta auditoria. Falta de catálogo aprovado é decisão funcional D08, não prova de falta de schema. Uma relação normalizada pode ser proposta depois se o contrato ou medições demonstrarem que TEXT não assegura a representação/consulta necessária; nenhuma necessidade de índice novo foi demonstrada.

**Abrangência:** REGIONAL não é sinônimo universal de Estadual. O adaptador deve delimitar a UF e não renomear cegamente registros antigos. LOCAL/MUNICIPAL e REMOTO/INTERNACIONAL também precisam de leitura de legado separada. A enumeração física mais ampla não impede oferecer os três valores ativos com contratos restritos; decisão de saneamento dos registros antigos permanece explícita (D09).

## 14. Comunidades — RF31/RNF12

Comunitário usa `comunidades` + `membros_comunidade`, não uma entidade hipotética `comunidade_membros`. Criador FK nullable, membros PK comunidade/usuário, papel e aprovado/data_ingresso. `aprovado=false` pode representar solicitação pendente, com operações transacionais de ADM e aceitação/recusa. API atual só GET lista/detalhe autenticados; PRIVATE não aparece para não membro. A regra ativa exige PRIVADA descobrível com conteúdo bloqueado; PUBLICA e PRIVADA são os únicos tipos admitidos na criação/edição. Criador/ADM único pode ser validado em transação, sem índice novo por hipótese. Saída/ban revoga acesso imediato, desban não reingressa/restaura participações. Requisitos da comunidade são declaração, não motor automático de elegibilidade.

4. RNF17 pede padrão20/max50; Agenda atual aceita100/padrão30, Comunidade usa12; função SQL sugestão limita até100. Corrigir contratos usados pelo backend, sem propor índices sem medição. Endpoints legados `UsuarioService.listarTodos`/listas profissionais também precisam de revisão de paginação/autorização; existência de lista limitada em uma API não certifica todas.
5. Catálogo profissional reduzido e nomes legados de testes (“Database04”, RF24 para chat, RF31 para estado de vaga, RF25 para cancelamento) não mudam fonte atual. O bootstrap dos testes aponta database05/46 arquivos/hash e `ddl-auto=validate`; inspeção de código de teste não é nova execução desse bootstrap.

Nenhum resultado novo de Maven/Semgrep/cobertura/performance/backup/browser foi produzido. Foram inspecionadas fontes Java de testes, casos e assertions das famílias existentes; muitos consolidam contratos anteriores (5/5 vaga, uma categoria afirmativa, PENDENTE e aviso de favorito ao dono). Teste existente não certifica baseline revisada; próximo trabalho deve atualizar expectativas de negócio mantendo negativos de ownership/privacidade/concorrência. RF22 continua **PARCIAL**, RF35 e RF36 também não são concluídos globalmente pela mudança documental.
